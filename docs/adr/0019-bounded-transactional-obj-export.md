# 0019 — Bounded transactional OBJ export

Status: **Implemented on export-core-01; automated qualification complete,
remaining acceptance gates recorded as PARTIAL.**

Date: 2026-09-30

Builds on ADRs 0008, 0015, 0016 and 0017. OBJ formatting, canonical ownership,
units and materials remain unchanged. STL and 3MF retain their existing paths.

## Problem

The RELEASE-06 truck produces 267,988,767 OBJ bytes. Buffered export retains
encoded chunks, concatenates a complete byte array, decodes complete text,
builds parser number arrays and a vertex-remapping Map, reconstructs geometry,
and allocates expected geometry plus corner-comparison arrays. Release
qualification observed a 2,329–2,342 MiB renderer peak.

## Decision

`ExportSink` separates byte storage from serialization:

```ts
interface ExportSink<Result = void> {
  write(chunk: Uint8Array): Promise<void>;
  close(): Promise<Result>;
  abort(reason?: unknown): Promise<void>;
}
```

One production OBJ serializer serves both resource classes. The page and export
worker independently route from the same conservative upper bound:

- At most 32 MiB estimated output: buffered validation and automatic Blob download.
- Above that bound: user-selected `FileSystemWritableFileStream`, bounded chunks,
  and mandatory streaming production-reader validation.

The bound counts every placement's vertices and faces and includes worst-case
UTF-8 metadata. Existing output and import ceilings are unchanged. The scalar
estimate routes storage; exact encoded byte accounting enforces the output ceiling.

The save picker is invoked under the Export click's user activation. No export
worker or geometry snapshot starts before selection and writable creation succeed.
Picker cancellation is neutral. A missing qualified file API produces an honest
capability failure; it never falls back to a large Blob.

## Validation remains mandatory

`readObjRecordStream` owns the production OBJ lexer and record semantics. Buffered
import collects those records into its existing document builder. Streamed export
feeds a fresh incremental UTF-8 decoder from the exact encoded bytes and checks
all coordinates, corner indices, names, group starts/extents and material references
against the source contract. It does not construct a second geometry document.

The consumer is independent of writer formatting. Parser and semantic failures
wake the producer immediately. A rendezvous acknowledges consumption only when
the parser requests the next piece. Only then may the same bytes be transferred
to the file sink. EOF, final counts and object boundaries must validate before
`file-ready` authorizes close. There is no skip-validation option.

This matches ADR 0016's generated-byte parse-back guarantee: buffered export
also validates generated bytes before Blob/download delivery, rather than
reading a file from the user's disk. Native stream integrity and atomic publication
are browser filesystem guarantees.

## Memory invariant and backpressure

Production chunks are at most 256 KiB. Text accumulation is bounded to that many
UTF-16 code units; a worst-case UTF-8 encoding needs at most three times that
space. UTF-8 byte seams are invisible to the streaming decoder. Partial views
are copied into exact-sized transfer buffers; whole owned buffers transfer directly.
Encoded lengths are captured before transfer detaches buffers.

One chunk may be in flight. The controller sends an ACK only after native write
completion. Neither parser rendezvous nor disk delivery has an accumulating queue.
The existing disposable geometry snapshot still copies each distinct mesh once:
that geometry cost is reported separately from bounded serialized-output memory.

## Cancellation and publication

Cancellation terminates the disposable worker and aborts the native transaction.
It cannot detach authoritative geometry. Replacement or another authoritative
revision cancels the session; a live conversion-token check also guards each
write and commit. Repair commit and undo are blocked while export is working.

Until `close()` is submitted, cancellation leaves an existing target unchanged.
The picker may create an empty placeholder for a new file. Once atomic close is
submitted, publication is the transaction's linearization point: that short native
commit completes as success or failure, rather than falsely claiming cancellation
of an already committed artifact. No application-created partial OBJ is published.

## Alternatives and support

OPFS writes and file-backed downloads keep renderer memory small in a regular
Chromium profile, but private-context OPFS can be memory backed and staging adds
another full file. It is therefore not a production dependency. Retained Blob
parts still hold the complete output and showed a large constructor peak.
No existing repository streaming-download mechanism was found.

Qualified scope remains desktop Chromium with native file access in a secure
context. No browser-support expansion, dependency, network permission or CSP
change accompanies this decision. Future formats can reuse the sink lifecycle
without migrating STL or 3MF now.
