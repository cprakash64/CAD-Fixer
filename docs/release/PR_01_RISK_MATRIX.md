# PR-01 — production release risk matrix

Audit of `e6520e7` (UI-06) for one question: _is CAD Fixer ready to be deployed
and used by real users safely, reliably and predictably?_ Every row is backed by
something that was run; the evidence was kept outside the repository.

Severity: **P0** data loss / security / unusable · **P1** serious correctness or
reliability · **P2** meaningful quality · **P3** polish or debt.

**Classification: GO WITH KNOWN NON-BLOCKERS** — no open P0, no open P1; the
remaining items are listed under _Known non-blockers_.

## Baseline (before any change)

`npm run verify` 135 files / 3,132 passed / 5 skipped · `test:e2e` 247 passed,
2 skipped · `test:e2e:harness` 130 passed · `test:e2e:timing` 15 passed
(cancellation ratio 0.635). No deterministic failure.

## Final verification (after the fixes)

`npm run verify` 136 files / 3,165 passed / 5 skipped · `test:e2e` 258 passed,
2 skipped, 1 failed under host load average 106 (conservative-repair O3, a 30 s
test timeout) which passed on a quiet re-run in 4.2 s · `test:e2e:harness` 130
passed · `test:e2e:timing` 15 passed (ratio 0.564). The full e2e suite runs
under the production CSP. Critical journey, clean context, production headers:
Chromium 151 and WebKit 26.5 pass every step with zero console errors.

## CI tiering

CI runs format, lint, typecheck, unit tests, the build and the Chromium e2e
suite on every push and pull request — and since PR-01 that e2e suite runs under
the production CSP. The harness (≈6 min, serial) and the timing proofs belong in
a pre-release tier rather than every PR: the timing proofs are only meaningful on
a quiet machine. `npm run release:check` runs all four gates in order for that
tier.

## Deployment actions required before the next public release

1. Reinstall `deploy/nginx/cad-fixer-security-headers.conf` on the host so the
   CSP, `Permissions-Policy` and `X-Frame-Options` are sent.
2. Deploy a build containing the new `third-party-notices.txt`.

## Not in scope

The capabilities the reference design shows and CAD Fixer does not have are
catalogued in `docs/design/UI_CAPABILITY_GAPS.md`; none is a release blocker,
and no document claims them.
